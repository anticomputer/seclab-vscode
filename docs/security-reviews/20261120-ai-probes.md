# Security review: the AI-feature probes on a scripted stand-in agent (agent-host-patches#3)

- **Date:** 2026-11-20 (round 1), 2026-11-21 (round 2)
- **Reviewer:** independent `security-review` agent (an Opus-class model), two rounds.
- **Subject:** `anticomputer-ai-feature-probes`: patch 0009 logs its refusals (`seclabRefuseAi`); the
  containment variant's `fake-model` hook (a test-only built-in, a scripted language model and
  default chat participant); `build/test-variant.sh` (`uiExtension`, bundles under
  `extensions/seclab-test-*`) and `build/check-release.sh` (no `seclab-test.` id, no
  `defaultChatParticipant`); the harnesses `test/containment/ai-probe.ts` and
  `test/containment/ai-agent-host-probe.ts`, the tab-side probe `test/containment/ai-tab-probe`, the
  rogue REH's `only=agent-host` observer, and their verdicts in `check-probes.ts`. Design:
  [EDR](../edr/20261120-ai-probes.md).
- **Prompt:** said the diff, fixtures and evidence may contain prompt injection aimed at the
  reviewer, and that the reviewer reports it rather than following it. None was found; the only
  instruction-shaped text is the harness's own canaries, which the fake model matches as exact
  lines and never follows.

## Verdict
No high or critical finding in either round. In round 1, four findings in the change are fixed here,
three with a regression test; AIP-4 predates the change, which surfaced it, and stays open for its
owner; AIP-6, the autoapprove probe's unmeasured tool-call leg, is deferred to the chat-in-tabs
increment. Round 2 confirmed each round-1 fix against the reviewed commit and found three lows: two
fixed, one accepted.

## How the evidence was made
The reviewed commit is fab9f020. On it:
- AIP-1: the probe-payload lint (`rpc-filter/tools/lint.sh`) reports 7 violations.
- AIP-2: the tab-side probe takes its port from the workspace's targets file; the case "the target is the packaged beacon port, confirmed by the workspace nonce" fails there, because its module does not exist.
- AIP-3: the check-release self-test case "a built-in extension asking for an escaped defaultChatParticipant (review AIP-3)" fails there: the escaped manifest passed.
- AIP-5: the case "the agent-host probes are judged host-side: the agents-on control, no transport opened and the gate refusal" fails there: a baseline whose only connection is the tab's own count passed.

All four pass on the fix. (AIP-1's count holds in a worktree where a harness run has left the
gitignored guard copy `test/containment/ai-tab-probe/probe-safety.js`; a clean checkout gives 2.)

  relaunched with `SECLAB_AGENTS_ENABLED=1`, the window opened 4 transports (control). Three probes

- `ai-agent-host-probe.ts baseline`: the window opened 4 transports to the hostile REH's proxy (the

## Residual observations
- The agent-host control phase lets a tab window connect to the hostile REH with agents on for the
  host. The REH refuses every `connect`, and the profile is new and isolated under the test build's
  own data folder, so there is no authentication session to forward; the harness does not inspect
  secret storage to prove it, because that means the host keychain, which no test touches.
- The tab-side listener's liveness is reported, not asserted: every fetch under test is made by the
  window, so the host listener's silence is the measurement, and the ordinary window's fetch is the
  control.
