## Round 7 (`264f63b..de19112` + 9e24cb7, re-review of N1)
Verdicts:
- N1: partially fixed. The reported bypasses are closed; three more silent blind spots were found (R1–R3).
- The 0:0 home-volume chown container (9e24cb7): safe. GNU `chown -R` uses `lchown` and never follows links, there is `EXDEV` across mounts, no tab is running at the time, setuid bits are cleared, and only `CHOWN` and `DAC_READ_SEARCH` are granted.
- Symlink pass: no hang, no read outside the workspace, and `cp` failures are not silent.
- Tar copy: can only be steered via R2.

| # | Sev | Area | Finding | Disposition | Fix / reason | Regression test |
|---|---|---|---|---|---|---|
| R1 | Medium | Scanner | Two kinds of link were still skipped: directory symlinks into excluded or allowlisted subtrees (`secrets -> .git/modules/stash`, files planted under `objects/`), and links that resolve inside the workspace only on the host (case-insensitive APFS, firmlinks). | Fixed | The git-dir copy excludes only well-formed object and pack files (`objects/xx/<38 hex>`, `pack-*.{pack,idx,…}`, LFS objects), so everything else under `objects/`, `modules/`, `worktrees/` and `lfs/` is scanned. Directory links into git-dir or allowlisted trees are copied and scanned under the link path. | R2 | Medium | Scanner | An absolute `commondir` written with the real host path skipped the common-dir scan. | Fixed | `inws()` maps the real path to `/scan/ws` for both git dir and common dir; anything outside both prefixes is `badgit` (blocking). | `test/secrets/run.ts` (`acd/.git/commondir` absolute) |
| R3 | Medium | Scanner | Unreadable or unlistable paths were skipped silently. | Fixed | Every file gets a real open (on Docker Desktop, `access(2)` reports readable while `open`/`stat` fail with ENOENT, which we verified), and `find`'s stderr is parsed. Self-found while fixing R1–R3:
- **Finding ids weren't deterministic.** gitleaks reports concurrently, `find` order varies, and dedupe-by-value keeps the first copy. A finding's id could change between the accept and the re-gate, which failed closed (blocked again) but flaked. Findings are now sorted per frame and link and HEAD lists are `sort -z`ed. Three OCI runs and one sbx run are stable.
- **Unit-test flake.** The supervisor's (dev, ino) workspace identity check tripped because Docker Desktop's bind-mount inode numbers are unstable. Test scratch now lives on a named volume.
- **CI (9e24cb7).** With the tab user on native Linux being the workspace owner, `seclab-reh-start` uses `/run/user/<uid>`, so the tmpfs now follows the uid, and `seclab-tab-env` tolerates a uid without a passwd entry.
