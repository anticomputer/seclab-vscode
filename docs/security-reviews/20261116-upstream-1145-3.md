# Security review: the Code-OSS 1.145.3 bump (round UB)

- **Date:** 2026-11-16
- **Scope:** round UB, by an Opus-class model: the upstream bump from 1.145.0 (`a717861c`) to
  1.145.3 (`dcd3ad6e`), which fixes the advisories microsoft/vscode published on 2026-11-10
  (affected < 1.145.3). It covers the 44-commit upstream diff against every patch in the queue,
  the bump commit, and the RPC inventory and drift check that certify it.
- **Threat model:** an upstream bump must not lose or weaken an upstream security fix through a
  patch that overrides the code it changes. It must not move an assumption a patch or the RPC
  policy relies on without a check noticing. And the checks that certify the bump must have
  actually run against the new upstream.

## Round UB
One medium. Confirmed:
- **Patch overlap:** only one file is changed by both upstream and the queue:
  `configurationService.ts`, touched by patch 0017. It applies with no fuzz, and its hunks are
  far from upstream's `updateWorkspaceTrust` change. Upstream's new untrusted-settings rules
  (`skipUnregistered`, ancestor scopes, `__proto__` hardening) act only on workspace and folder
  settings in untrusted workspaces. 0017 closes REH-supplied remote user settings in trusted
  `seclab+` windows, so it remains necessary and unweakened.
- **Patch 0036:** it can't carry unregistered or `__proto__` keys across. It requires a key
  registered for the tab, refuses prototype segments, and builds into null-prototype objects.
- **Assumption drift:** none. Patch 0015 types its AHP verdict tables against upstream's
  protocol maps, so a successful build proves the AHP shapes didn't drift.
- **Vectors upstream now also fixes:** agent-originated local commands, network workspace
  trust and renderer debug auto-attach all move in the safe direction, as defence in depth
  behind patches 0009, 0010, 0015, 0041 and 0007/0008.
- **The bump commit:** upstream.lock, the dependency register and the docs agree.
