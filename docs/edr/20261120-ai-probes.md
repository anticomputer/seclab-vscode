## Context
Finding agent-host-patches#3: six `ai-*` probes were declared and none ran. The dial probe landed
first. The other five need something in the window that acts on tab-controlled input, and an oracle
on the host side, because 0009 and 0010 refuse by throwing `Unsupported operation` with no trace a
run can read.

The plan was to give the built-in chat a fake model. Reading the pinned source (1.145.3) settled
that this cannot work by itself: core chat has no agent loop. Its only agent implementation,
`SetupAgent` (`chatSetupProviders.ts`), forwards every request to a default participant that an
extension registers (normally Copilot Chat) and times out when none does. This build ships no
Copilot Chat (0001); local windows run only ui-kind built-ins (0003); every other extension is
workspace-kind (0002), so an installed Copilot Chat runs only inside a tab. The remaining loops are
the agent host (none in the desktop app: 0013, 0014; a tab window reaches its tab's through
`agentHostProxy`, gated by 0010 and 0015) and the cloud sandbox.

## Decision
**A scripted stand-in agent, test variant only.** The `containment` variant gains the hook
`fake-model`: a ui-kind built-in (`seclab-test.fake-model`, marker `SECLAB_TEST_ONLY:fake-model`)
that is both a language model and the default chat participant, through the
`defaultChatParticipant` proposal its own manifest asks for (a built-in keeps the proposals it
names). It stands where Copilot Chat would. Core still does the part under test: it computes the
automatic instructions (`applyTo`, `copilot-instructions.md`) and hands them to the participant.
- It is inert unless a run arms it: `arm.json` in its storage in a test profile (`~/.seclab-test`
  or `.work`), with the run's nonce, an expiry of at most an hour and the actions. Each action is an
  exact canary line carrying the nonce and the URL to fetch, which must be the run's loopback
  beacon on a path naming the window and the nonce.
- Instruction text is data: an attached file "matches" only if it holds one of the armed lines as a
  whole line, and the match selects an armed action. The URL never comes from the text. It reads
  only files in a seclab tab's workspace or the test profile; core also attaches instructions from
  the user's real home, which it never opens.
- Its one action is the built-in fetch tool (`vscode_fetchWebPage_internal`) on that URL. Its model
  answers with a fixed string and contacts nothing.
- A trigger file from the harness makes the window ask chat, naming the fake model explicitly (an
  extension host resolves an unnamed model only to the Copilot vendor's default).

**Release safety.** `build/test-variant.sh` lets a hook add an extension under
`extensions/seclab-test-*` and name it in `uiExtension`; only the variant's `product.json` lists it
as ui-kind, and `verify` checks exactly those. `build/check-release.sh` refuses any `seclab-test.` id,
any `product.json` that grants `defaultChatParticipant`, and any built-in manifest that asks for it.
Its self-test injects each, and the fake model's marker.

**0009 logs its refusals** (`seclabRefuseAi`, surface `ai`, a closed set of keys and a fixed reason,
into the window's decision log): `ai:chat.sendRequest`, `ai:tools.invokeTool` and the two
registration keys. 0010's refusal already reaches the host-side gate log: it chooses the client by
0015's `seclabAgentHostAllowed`, which logs `ahp-gate.disabled`.

**Step 2, `test/containment/ai-probe.ts`.** A tab window and an ordinary window in one app.
- Control: the ordinary window's agent follows a user-level instructions file in the test profile
  and fetches the beacon from the host. The file is removed before the tab window asks.
- `ai-instructions-tool-call` and `ai-settings-reenable`: the tab's workspace holds the
  instructions and settings turning chat back on. Patched: the request is refused (the decision
  log), nothing is fetched, and the window reads the tab's settings (their control). Baseline: the
  tab window's agent fetches from the host.
- `ai-tab-invoke-tool` (arm B): an extension in the tab (`test/containment/ai-tab-probe`) calls
  `vscode.lm.invokeTool` on the fetch tool. The filter refuses `MainThreadLanguageModelTools.$invokeTool`
  (logged under its wire sid, `MainThreadChatSkills`), with 0009 behind it. The filter is in every
  build, so there is no baseline; the ordinary window's fetch is the control.

**Step 3, `test/containment/ai-agent-host-probe.ts`.** The rogue REH (`only=agent-host`) wraps
`agentHostProxy` as it is registered, counts every call and subscription, and refuses every
`connect`, so no agent host starts. The host user sets `chat.disableAIFeatures: true` and the tab
writes `false` into its remote user settings. Patched: with agents off for the host, nothing
arrives, no gated transport opens and the gate logs its refusal; the same app relaunched with
`SECLAB_AGENTS_ENABLED=1` does connect (the control). Baseline: the window connects.
`ai-agent-host-autoapprove-setting` is measured by that precondition only: a tab window opens no
agent-host connection, so no agent host can ask for a tool. The tool-call leg needs chat open in tab
windows, which it is not (project owner decision, 2026-11-17).

**The baseline build drops 0018 as well as 0009 and 0010.** 0018 is the second layer behind 0009 on
the same entry points: it refuses an extension participant's request in a tab window
(`deny:agents-off`, `deny:unresolved`). Without dropping it, a baseline could not show the path
0009 closes. The branch is build-only and is deleted after the proof.

Every judged fact is host-side (the beacon, the decision and gate logs, the fake model's record in
the test profile), with the REH's count as the instrument for step 3 corroborated by the gate log.
What the tab writes (its listener's log, the tab probe's record) is reported as its claim and never
judged.

## Consequences
- Five probes move from `not-implemented` to required, judged by `check-probes.ts` with patched and
  baseline predicates and mutants.
- The fake model is a reusable stand-in for later window-side agent tests; it is a test build hook
  and inherits the variant rules (never releasable, review per change).
- **Evidence:** see the review record for the runs.
