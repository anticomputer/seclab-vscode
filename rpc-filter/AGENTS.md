# AGENTS.md: rpc-filter

Instructions for an agent working on the RPC capability filter. Read the root
[AGENTS.md](../AGENTS.md) first; its hard rules apply here. Commands below have
actually been run; anything unbuilt is marked **TODO**.

## 1. What the filter guarantees, and what it does not

**Guarantees.** Code in a tab cannot reach a trusted-side capability that is not
explicitly listed as reachable in `policy/policy.json`. Anything unlisted is
denied, including surfaces upstream adds. Identity used for secret storage and
auth comes from the connection, never from call arguments.

**Does not guarantee.**
- That an *allowed* surface is safe. Reachability is granted per item after
  review, but review is fallible and the set grows in Phase 3.
- That an allowed command does not internally invoke a denied one. Verdict
  laundering is **undesigned** (residual risk 1) and is the most likely bypass.
  `_remoteCLI.windowOpen` → `_files.windowOpen` is the known shape.
- That the inventory is complete. The command scan uses regexes; 168 id
  expressions are unresolved. Misses are denied, so they cost compatibility,
  not containment — but a miss nobody notices stays invisible.
- That a verdict still matches behaviour. The digest pins ids and policy
  entries, not upstream implementations.

## 3. Regenerating the inventory

```sh
rpc-filter/tools/fetch-upstream.sh     # pins from upstream.lock, else a named constant
rpc-filter/tools/run.sh                # container, --network none, no install
rpc-filter/tools/check.sh              # exits 1 on drift, naming each surface
```

Both run in `python:3.12-slim`; nothing is installed on the host. The generator
is deterministic: same source in, byte-identical output. If `run.sh` produces a
diff with no upstream change, that is a bug in the generator, not noise.

## 4. Classifying a new RPC method or command

1. Read the implementation. Do not classify from the name or the category.
2. Add an entry to `policy/policy.json` with every field: `verdict`,
   `capability`, `impact` (worst case with **no** filter), `constraint` if
   `allow_with_constraint`, `residual_impact` only if the constraint genuinely
   removes an impact, `rationale`, and `evidence` permalinks pinned to the SHA.
3. For commands, reachability goes in `commands.exact` keyed by id. **Category
   rules may only carry `deny`** — the drift check enforces this. A substring
   heuristic may withhold authority; it may never grant it. This rule exists
   because the first draft allowed 389 commands by category, including ones that
   open external links.
4. Run `tools/check.sh`. Fix what it reports.
5. Run `tools/check.sh --accept` **only after reading the diff**. That command
   is the "I reviewed this" step; running it blind defeats the gate.

Keys: RPC entries are keyed on the wire `sid` from `createProxyIdentifier`,
never the `MainContext` property name (7 diverge) and never the numeric `nid`
(module-load-order dependent). `check_keys` rejects the wrong one by name.

## 5. Reading a drift-check failure on an upstream bump

| Failure | Meaning | Do |
|---|---|---|
| `NEW rpc:…` / `NEW cmd:…` | Upstream added a surface. It is already denied. | Classify it, or leave denied deliberately, then `--accept`. |
| `CHANGED …` | A verdict or a reachable entry's content changed. | Confirm it was intended. A `constraint` edit lands here by design. |
| `REMOVED …` | Upstream dropped it, **or** the generator stopped finding it. | Check which. A silent extractor regression looks identical to a real removal. |
| `policy.commands.exact['x'] is not in the inventory` | The **scanner** missed a registration form. | Fix the generator, not the policy. Sibling commands registered the same way are also missing. |
| `… is reachable through a category rule` | Someone granted authority in bulk. | Move it to `commands.exact` with a review. |
| `… claims reduced residual impact but names no constraint` | Relabelling, not mitigating. | Write the constraint or change the verdict. |

## 6. Adding a probe (Phase 3)

**The rule: a probe must SUCCEED against the unpatched build before the patch
lands.** A probe that has never passed proves nothing — it may be failing
because the test is wrong. Record the before-and-after in an EDR.

1. Extend the shared rogue extension (owned by the fork-build session). Do not
   create a parallel one.
2. For server-side surfaces — channels, server-initiated callbacks — use the
   **rogue REH** fixture, not the extension: the extension host cannot reach
   them.
3. Run it against the unpatched build; record that it succeeds.
4. Apply the patch; record that it fails.
5. Add the canary assertion: the probe must not observe any seeded canary in any
   encoding (raw, base64, URL-encoded).

## 7. Invariants that must never regress

1. **Default-deny.** Anything unlisted is denied. Never add an allow-by-default
   path, and never make a category rule grant.
2. **No real secret in a tab**, in any form, through any surface. Credential
   surfaces are `deny` or `rewrite` — never `allow`, `allow_with_constraint` or
   `prompt`.
3. **Identity never from arguments.** Tab and extension identity are bound to
   the connection. `$getPassword(extensionId, …)` and `$getSession`'s
   `extensionId` are the reason this is written down.
4. **Key on the wire `sid`.**
5. **Fail closed on attachment.** An unregistered `seclab+*` authority is fatal;
   anything that is not a known tab or the trusted local kind gets a deny-all
   filter. `remoteAuthority` being `null` must never mean "no filter".
6. **The argument walker matches `marshalling.revive`**, including the depth-200
   cap, and rejects graphs deeper than the cap rather than guessing.
7. **Every reachable surface has a reviewed entry recording an impact.** The
   drift check enforces this across the whole mapping.

## 8. Probe safety: never attack the host

On the **unpatched** build a "successful" probe really executes on the user's
Mac. The probe set is a working exploit chain against the machine it is
validated on, so every payload is inert by construction.

These are enforced three ways: `probe-safety.js` at runtime,
`rpc-filter/tools/lint.sh` at review time, and
`test/containment/probe-safety.test.ts` on the guards themselves.

1. **Success demonstrates reach, nothing more.** Host code execution means
   writing one fixed marker file under the run directory, built only by
   `safety.markerCommand()`. No other shell, no downloads, no persistence, no
   deletes, no process control, no settings changes.
2. **Reads touch only harness-seeded canaries.** Never `~/.ssh`, `~/.aws`, the
   keychain, real editor or browser profiles, or other repos. Every path goes
   through `safety.safePath()`, which resolves symlinks and refuses anything
   outside the run directory.
3. **Fake credentials only**, in the isolated user-data-dir. Never the user's
   real GitHub or Microsoft sessions. Seeded keychain entries are namespaced
   per run and removed in teardown, including on failure.
4. **Network only to the harness beacon** on `127.0.0.1`, via
   `safety.safeUrl()`. No external host, ever.
5. **Extension and window probes are reversible** and act only on fixtures
   inside the run directory or the isolated profile. `manageExtensions` lists;
   it does not install. `openExternal` targets the beacon, so no real browser
   opens.
6. **Arming.** Probes are inert unless the harness supplies a per-run nonce in
   `SECLAB_PROBE_NONCE` **and** a matching `.seclab-probe-nonce` file in the run
   directory. Environment alone does not arm them, so the extension installed
   anywhere else does nothing.
7. **Teardown** removes markers, keychain entries, sandboxes and windows, and a
   post-run check asserts nothing outside the run directory changed:

   ```sh
   node test/containment/teardown.ts snapshot <run-dir>   # before the run
   node test/containment/teardown.ts verify   <run-dir>   # after it
   ```

   `verify` is a tripwire over `$HOME`, `~/Library/LaunchAgents`, `~/.ssh`,
   `~/.aws` and `~/.config`, plus the run-scoped keychain key and any sandbox
   left running. It is not a guarantee; it is the thing that notices.

8. **A run never takes the user's screen.** Launch the editor with
   `open -g -n` (or a direct background exec), never activate or focus it, and
   tear it down as soon as the run ends. `-g` keeps it out of the foreground;
   `-n` forces a new instance so the run cannot attach to a window the user
   already has open.

   This is a safety rule, not a courtesy. A probe run drives a *hostile*
   workspace, so a window that steals focus can take a keystroke meant for the
   user's own work, and an orphaned one leaves an armed rogue extension sitting
   on the desktop — which has already happened once, and the user found it
   before teardown did.

A safety refusal throws `SafetyError`, which is tagged so `classify()` records
it as `ERROR`. It must never be scored as a denial: a mis-targeted probe would
otherwise read as containment.

Adding or changing a probe means re-running `rpc-filter/tools/lint.sh` and the
safety unit tests, and a security review round before the next unpatched run.
